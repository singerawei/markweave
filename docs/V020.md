# 0.2.0 implementation and validation

Windows x64 development release. The installer bundles Chromium headless shell and Playwright runtime; no external browser, download or cloud rendering is used at runtime.

## Interface mapping

Office Viewer is a reference for Markdown authoring, not for its unrelated Office, Git or AI features. MarkdownUP retains its source-owned ProseMirror model.

| Reference capability | MarkdownUP entry |
| --- | --- |
| Headings, emphasis, strike, inline code, quote, list | Icon toolbar; H3-H6 in Insert |
| Ordered list, task list, indentation | Insert menu |
| Link, image, horizontal rule, code, table | Insert menu |
| Table rows/columns and header operations | Insert menu while a table is active |
| Emoji, insert block before/after | Insert menu |
| Undo/redo | Toolbar and native shortcuts |
| Fullscreen/focus, outline, find | Toolbar |
| Source, preview, visual editing | More menu; Reveal source; native Text Editor escape hatch |
| Content/code appearance | More menu |
| Export | PDF toolbar, command palette, webview context menu |
| Help/info | More menu |

No microphone recording, cloud image upload, AI integration or developer console is exposed. Image insertion accepts local relative paths. Emoji currently inserts a standard smiley rather than a searchable emoji catalog. There is no two-pane whole-composition source editor; source editing remains source-owned and local to a block or the native source file.

## Rendering and export

One active editor, viewport chunk mounting and streamed metadata remain in place. Mermaid is rendered in a separate Chromium process with a serial task queue, strict Mermaid security, local scripts, blocked network requests, cached SVG and a 15-second per-render timeout. Distant queued blocks are skipped before starting. Chromium closes after idle and on extension disposal. Export starts a separate browser and always closes it in a finally block.

PDF export snapshots all current source pieces, including unsaved edits and content outside mounted chunks. Missing imports/images and invalid diagrams abort export; output is written through a temporary file only after successful rendering. Text remains searchable; diagrams remain SVG in the print document. The sample PDF includes Chinese, an unsaved child edit, a diagram, header, footer and page count. Local PDF preview files live in a temporary directory.

## Checks and scope

Run `npm run check`, `npm run test:ui`, `npm run test:host`, `npm run package`, then `node scripts/test-host.mjs markdownup-win32-x64-0.2.0.vsix` for an isolated installed-package check.

The host suite covers PDF generation with unsaved source preservation, backup/restore and six performance cases. Mixed cases contain 20 or 100 diagrams, including a 100-include composition. First-text, first-edit and first-diagram timings are recorded separately in `bench/results/vscode.json`. The input and scroll numbers are synthetic frame measurements; these do not certify all IMEs or every diagram syntax and hardware combination. Inspect the latest raw measurements rather than treating older 0.1.0 numbers as this release's results.

Remaining acceptance limits: no automated pixel comparison against Office Viewer; no exhaustive Mermaid syntax matrix; no cross-platform release; no long-duration real keyboard/IME soak test. The full v1.0 release checklist is not certified by this development package.
